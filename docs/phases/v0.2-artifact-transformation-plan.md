# PhiOffice369 v0.2 Artifact Transformation Plan

**Phase:** `v0.2-artifact-transformation`  
**Status:** Open / active planning  
**Foundation:** `v0.1-greencheck-foundation`  
**Primary thesis:** A document is not just a document. It can become a deck, checklist, README, project packet, export bundle, and Vault-tracked living artifact.

## Phase intent

v0.1 proved the local-first foundation. v0.2 should prove PhiOffice369’s signature workflow: artifacts can transform into other useful artifacts while preserving provenance, trust labels, receipts, and compatibility honesty.

This phase should avoid broad new app sprawl. The priority is depth over width.

## North star workflow

```text
PhiWrite document
→ transform packet
→ PhiDeck deck
→ README/checklist/export bundle
→ export receipts
→ PhiVault continuity timeline
```

The user should feel that one good artifact can become many useful outputs without losing track of where it came from.

## Core v0.2 outcomes

### 1. Transformation Registry v0.2

Create a stronger registry for known transformations:

- PhiWrite → PhiDeck
- PhiWrite → README
- PhiWrite → checklist
- PhiGrid → summary report
- PhiDeck → speaker notes
- Workspace → launch packet

Each transform should define:

- transform ID
- source app
- target app or target artifact kind
- input shape
- output shape
- trust label defaults
- compatibility warning defaults
- receipt metadata
- public risk notes

### 2. Transform Packet model

Introduce a versioned transform packet that can carry:

- source artifact metadata
- transform trace
- generated artifact payload
- trust labels
- compatibility notes
- warnings
- createdAt timestamp
- local-only marker

Suggested schema:

```text
phioffice369.transform_packet.v0.2
```

### 3. PhiWrite → PhiDeck depth pass

The existing bridge should become more expressive:

- parse headings into slide titles
- parse paragraphs into slide body bullets
- detect numbered sections
- create overview / next-step slides
- carry trust defaults
- create transform trace
- save or expose a receipt
- allow PhiDeck to display source artifact metadata

### 4. PhiWrite → README / Checklist

Add local utilities that convert a document into:

- README draft
- build checklist
- launch checklist
- issue/task outline

These can begin as exportable Markdown artifacts before becoming full UI surfaces.

### 5. Vault transform timeline

PhiVault should be able to show:

- source artifact
- generated artifact
- transform ID
- createdAt
- export receipts
- warnings
- trust labels

This makes the transformation history visible instead of magical.

### 6. Export bundle v0.2

Add a simple workspace/export packet concept:

- source artifact JSON
- generated artifact JSON
- Markdown export
- receipt JSON
- compatibility report JSON

This does not need ZIP support yet. A plain JSON bundle is enough for v0.2.

## Out of scope for v0.2

Do not claim or prioritize:

- full DOCX/XLSX/PPTX round-trip compatibility
- cloud sync
- backend AI integration
- full PhiNotes/PhiMap/PhiBase app builds
- production-grade file-system access
- multi-user collaboration

## Phase guardrails

1. Every transformation must be local-first.
2. Every AI-assisted or generated result must carry visible provenance.
3. Every export should have a receipt where practical.
4. Compatibility limits must be visible.
5. Big UI changes should be preceded by small tested helpers.
6. PhiVault must not treat control-plane keys as user artifacts.
7. Green checks are the build truth.

## Suggested implementation sequence

### Step 1 — Phase docs and changelog

- Add this phase plan.
- Add an Unreleased v0.2 section to the changelog.

### Step 2 — Transform packet helpers

- Add `transformPackets.js`.
- Add tests for packet creation and validation.

### Step 3 — Expand transform registry

- Add transform definitions for README/checklist/bundle flows.
- Add tests for registry lookup and labels.

### Step 4 — PhiWrite transform utilities

- Add document-to-deck parser improvements.
- Add document-to-README and document-to-checklist helpers.
- Add tests before UI wiring.

### Step 5 — UI wiring

- Add transform actions to PhiWrite-lite.
- Add transform preview cards.
- Add clear receipt/trust metadata.

### Step 6 — Vault timeline

- Save transform traces or receipts.
- Show transform lineage in PhiVault.

### Step 7 — Green-check checkpoint

- Run tests and build.
- Document v0.2 completion state.
- Release when stable.

## Success criteria

v0.2 is successful when a user can:

1. open or write a PhiWrite artifact,
2. transform it into at least one deck and one Markdown derivative,
3. see trust/provenance metadata,
4. export the result,
5. find the transform trail in PhiVault,
6. pass tests and build cleanly.

## Build truth command set

```bash
npm ci --no-audit
npm test
npm run build
```

## Claim boundary

v0.2 is an artifact-transformation prototype phase. It proves local-first transformation workflows and visible provenance. It does not claim production Office replacement status or perfect compatibility with third-party document formats.
